# 函数筛选格式的最小修正与全量重跑

用户要求：修复 62 道函数筛选标签数量不符的问题，遵循论文思路，修改尽量小、严格公平，不根据标准答案调整，并重新运行全部 238 题。

## 原因与修改

旧输出为 30 个无编号 `USEFUL/USELESS` 标签，与 30 个函数按位置对应。仅检查旧筛选响应的格式，62 个失败输出包含 27–36 个标签，另有一例 81 个。缺项或多项时不能可靠推断对应关系，因此不能通过截断、补齐或猜测位置恢复选择。

新协议 `candidate-ids-v2` 给按原检索顺序排列的候选固定编号 `C01` 至 `C30`，模型只返回 JSON 对象中的 `selected_ids`，包含零至三个不同的已有编号。相关性判断仍使用作者关于功能、输入、输出、适用范围和限制的原标准；与旧实现一样，按检索顺序保留最先判为有用的最多三个函数。没有有用函数时允许空选择。

筛选请求增加 JSON Schema 约束，限定字段、编号范围和最多三个选项；本地继续检查未知编号、重复编号、超额选择、重复 JSON 字段等，不能因网关接受 schema 就省略验证。仅对输出选择集合做检索顺序的规范化，不改变所选集合。

这将原本长度为 30、依赖位置计数的序列改成最多三个显式引用，直接落实论文“从 30 个候选中选择最多 3 个有用函数”的环节。没有增加模型、推理分支、答案反馈或选择失败后的再次提问。

## 公平性约束

- 对全部 238 题统一采用新协议，不只重做旧的 62 道失败题。
- 新运行使用独立空缓存和空输出目录，全部查询、筛选及 PoT 都重新调用；不拼接上一轮答对题的输出。
- 协议开发只使用旧筛选输出的语法问题及合成测试，不用真实标准答案或旧答案的正误来选择规则。
- 查询和 PoT 模板、函数原文、3,133 条函数、检索器及其索引、候选数 30、选择上限 3 均不变。
- `gpt-5.6-sol`、服务地址、温度 1.0、top-p 1.0、最大输出 8,192 tokens、执行器与 0.2% 相对误差评分均不变。
- 一次筛选、一次生成；无格式纠错模型调用、截断补齐、默认 top-3 回退或答案条件重试。接口故障仅按原传输规则处理。
- 全部预测保存后才评分；本轮不根据中途准确率改变代码、提示词或设置。

75 项测试通过。合成的 API 格式探针已确认服务以 200 返回所请求的 JSON 编号；该探针不包含任何真实评测题。正式运行前，代码、配置和资产哈希及这些规则已写入 `research/ids_v2_preregistered_protocol.json`。

