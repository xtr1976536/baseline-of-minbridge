## 核心方法

保留论文的 OQA、OES、OMD、OPE、直接证据优先、缺失拒答、子目标及多公式并行、单次路径审核、共识投票、完整约束缓存和有限一跳反解。提示词正文仍来自附录 F；未公开的格式槽由明确 schema 填充，没有增加额外 judge 模型。

补充了证据的 `observed_meta`，记录原文显式单位和尺度，数值仍原样抽取。父指标的比例单位不会错误地传给货币操作数；程序阶段根据显式单位做归一化。币种矛盾会被拒绝，不能编造汇率。期初权益仅对明确的年度约束使用上年期末映射；季度或跨年范围不能简单减一年。

## FMKG 的重建

入口：`gbfr/build_graph.py`。唯一原始知识库输入是作者固定提交中的 `term_en_final.json`，SHA256 为 `67f2ff0393308352992fbef88777275b09adfd26a4042541fc395eed9e4be06a`。构图函数不接收测试集或预测，完全不读取问题、标准答案或解题标注。

处理规则：

1. 合并大小写/标点变体、明确的全称缩写和论文明确列举的别名，保留时间、调整口径等语义限定。不因共享缩写就合并不同指标。
2. 只从完整可解析的数值等式生成计算边，逐公式绑定操作数，不把引用等非计算关系当边。源文件缺少节点记录但明确出现在有效公式中的操作数，补成仅直接取证的叶节点；辅助等式绑定到实际左端指标，不能错绑到文章标题。
3. 参考 Python 代码只做 AST 静态解析，绝不执行。可比较时核对公式与代码的输入和数学表达式；不能解释的冲突排除整条公式。无法静态比较的公式保留源等式和明确绑定，不声称完成专家财务核验。
4. 论文图 1–2 的 `ROE = Net Income / Average Equity`、期初/期末权益，以及图 4 的两条 Cost of Sales 公式优先于冲突的源记录。没有采用论文举为错误示例的“净利润 / 期末权益”替代 ROE。
5. 按“论文明确公式 → 公式/代码一致性 → 财务派生指标优先级 → 较少操作数 → 源公式多样性 → 稳定哈希”确定规范计算方向。造成环或超过论文 A.3 报告的六层构图深度时，排除整条候选并留审计记录，不删除其中一个必要操作数。反向使用由运行时一跳代数反解处理，不额外加入反向边。
6. 同一输入与数学关系的重复记录、交换次序和输出尺度变体合并，保留所有来源，不能借重复公式增加共识票数。不同财务输入、年份或实体角色的路径分别保留。

当前资产 `data/assets/fmkg.reconstructed.json`：**11,619 节点、8,349 直接取证叶节点、3,270 派生节点、11,889 依赖边、4,844 条公式，最大深度 6**。叶节点含源公式明确需要、但原始记录没有独立定义的操作数；因此节点数高于论文的 7,521，并不是添加虚假节点凑统计。这里的 atomic 是重建图中“没有启用规范公式”的运行角色，不冒充作者对所有指标语义不可约性的专家判定。

保留公式中，1,211 条与静态参考代码等价，3,628 条因参考代码不可静态核对而以源等式为依据，5 条来自论文明确示例。排除 102 条循环/反向候选及 259 条超过六层的候选；其他无法绑定、无法解析或公式/代码冲突也逐条记录。以上不是人工专家已全部验证的声明。

审计：`research/reconstruction/graph_build.json`、`graph_formula_decisions.json`、`graph_direction_exclusions.json`。原始源、公式来源、未启用原因均保留，可从固定输入重新构建。
