# 固定 35 题修订与验证

本轮按用户新要求将本地验证规模改为 35，继续只做 FinanceBench 的 VeriFin 主模型，接口仍为 GPT-5.6 Sol。没有启动新的 67 题全量、其他数据集或其他实验。

## 先修复、后运行

正式 35 题之前，84 项回归测试通过；还使用原始财报做了不调用 GPT 接口的实际检索检查，确认 AMD 的 D&A/收入、Coca-Cola 的分红/股东净利润、AES 的合并净利润/总资产均进入选中的证据集合。检查记录在 `research/validation35_preflight_retrieval.json`。Nike 库存和 General Mills 应收余额的 XBRL 绑定也在运行前核对，数值未用于选择概念。

| 问题 | 本轮修复与限制 |
|---|---|
| 原始 HTML 被抽成“标签、数字各占一行” | 从同一已冻结 HTML 的原始 table/tr/td 重新渲染行，保留数字、括号符号、年份与单位；原文和原数据文件不改。只增加同文件的表格证据页，来源哈希必须一致。 |
| 母公司附表或脚注挤掉主合并报表 | 对问题要求的报表类型保留少量主报表召回候选，仍执行混合得分及同一交叉编码器重排；有界 top-16 优先保留匹配操作数的主报表行，不扩大为全文输入。 |
| 分红在现金流表中只写作 Dividends | 仅在现金流分红角色的检索别名中加入该词；绑定仍按已记录的支付分红概念与期间进行。 |
| 总库存采用 finished-goods 标签、净应收采用另一标准 qname | 增加两项有来源的条件映射：只有 issuer 行明确呈现为总库存/净应收余额时才允许；finished-goods 组件标签不能冒充总库存。库存与应收绑定必须是 instant，不能取同年现金流变动。 |
| 比率公式与百分数显示单位不一致 | 题目定义的货币比率以百分数输出时，仅做一次 ×100 的单位表示转换；已有 ×100 的公式不重复换算。转换完全不读取候选或金标。 |
| EBITDA 混入题目未指定的其他摊销 | 题目明确用 operating income 和 D&A 时，从公开注册表的允许模板中保留该加回范围，不自动加入另列的内容资产摊销；问题明确提到这些项时不作该收窄。 |
| 检索证据不完整时 planner 直接放弃数值任务 | 规划仍列出问题或注册表已明确的 primitive roles，缺失事实由 provenance 阶段决定弃答。不能用常数 0 代替“未披露”的证明。 |
| 过早舍入导致正确财报计算被拒绝 | 初始生成遵守题目明确精度；没有要求时，金额保留财报精度，计算结果至少六位有效数字。未增加答案修复、反馈或重采样，验证器容差也未按结果改宽。 |
| Cash-flow/note 金额被当作“损益表直接列示” | 严格声明 directly/explicitly outlined in income statement 时，要求相应概念具有该主损益表的来源关系；不能以附注分配中的 0 或现金流加回项目证明。来源不完整仍弃答。 |

保留问题与金标。特别是某条“损益表直接列示”的参考金额实际出现在现金流表，这种来源冲突不靠改题、改答案或删题解决；无法满足原问题的来源条件时保留弃答。

## 35 题与参数冻结

复用此前种子 `verifin-coverage-50-v1`，在原 67 个 ID 上取 SHA256(seed|id) 最小的 35 个，再保持原数据集顺序。清单先于本轮修改和预测固定，未搜索种子或根据旧分数换题。清单为 `research/validation35_manifest.json`。

三项数值门槛仍取论文 Table 4 FinanceBench/GPT-5.5：接受精度 100%、决策准确率至少 86.7%、覆盖率至少 70.1%，且全部 35 题完整、无运行错误。35 题至少需要 25 个非弃答判定才能满足覆盖率门槛。

模型和两个检索 checkpoint、来源文件、输入缺失状态、配置、代码以及两种评分规则在正式运行前固定。配置为 `configs/validation35-v1.json`，运行计划为 `research/validation35_run_plan.json`。验证配置严格限定 35，错误使用 34、36 或 67 个 ID 会被拒绝；不能以全量 run 命令启动该配置。

## 评分口径单独说明

原始 FinanceBench §4.1 使用人工标注，允许微小舍入误差，没有发布统一数值阈值。上一轮自行采用的“参考标签显示小数位”严格评分不等同于该人工规范，例如它会把精确源值 1615.9 对格式化参考 1616.00 判错。

本轮在跑题前提出评分澄清；没有收到回复时，已向用户说明暂按推荐选项固定本地操作化，并完整并列保留旧严格结果。**本地规则不是作者公布的官方数值阈值**：

1. 题目明确要求的小数位优先。
2. 无明确要求时，只有货币参考值去除末尾格式补零，再以信息小数位的半 ULP 比较，最多粗到整数单位；货币零值精确匹配。
3. 百分比、比率等其余标签继续保留其显示精度；单位换算和无法唯一解析的未决规则保持一致。
4. 验证器不读取参考答案，以上规则只在完整验证结束后评估候选正确性。

`financebench_currency_padding_v1` 为本轮声明的主口径，`legacy_display_precision` 的逐题判断、分数与误判同时保存。修改前同 35 题也按相同两种规则重新计分。评分规则自身造成的提升不计作模型改进，不能混用两套分数来通过门槛。

```powershell
python -m pytest -q

```

本轮更改检索及初始生成输入，每题至多形成一个初始候选并缓存；模型拒答、不可用答案及弃答均保留分母。修改前与本轮是同问题、不同候选的端到端比较，不能归因成相同候选下的纯验证器收益。

| 决策准确率 | 95.65% | 100% | 86.7% |
| 覆盖率 | 65.71% | 82.86% | 70.1% |

| 弃答 / 正确性未决 | 12 / 0 | 6 / 0 | — |
| 运行错误 / 遗漏 | 0 / 0 | 0 / 0 | 0 / 0 |

覆盖率增加 17.14 个百分点。恢复的 6 题为 AES ROA、AMD D&A margin、Coca-Cola 分红比例、General Mills CCC、Netflix EBITDA margin、Nike 库存周转率。原 PepsiCo EBITDA margin 误拒绝也已消除：新初始候选保留计算精度，验证容差没有改宽。另有 2 个候选算错最终值，被正确拒绝。

旧严格显示精度口径：精度 76.19%→81.48%，决策准确率 73.91%→82.76%，覆盖率同为 65.71%→82.86%；仍未全部达门槛。主口径的精度在修改前已经是 100%，不能把旧严格分数切换成主规则的差异说成模型精度提升。

5 个评分分歧均为与财报值或授权小计相等、参考金额较粗舍入的情况，分别是 8.738 对 8.70 十亿美元、1615.9 对 1616.00 百万美元、0.389 对 0.40 十亿美元、381.603 对 382.00 百万美元、5466.312 对 5466.00 百万美元。它们的原始答案、单位、公式和源事实均保存在对照文件中。

29 份 SMT 重放一致；另用独立 Fraction 算术和源事实 ID/期间/单位换算核对全部 29 个判定，CAGR 则用有理数幂区间作精确判定，全部一致。所有 35 个初始响应已作代理逐题复查，未发现被接受响应中相互矛盾的财务操作数或运算；这不是作者的人工作答标签，也不把 SMT 一致性当作金融语义的形式化证明。记录见 `independent_arithmetic.json`、`candidate_review.md`、`response_review.json`。

因此，**本轮预先固定的主规则下三项数值门槛通过；旧严格规则下仍未全部通过**。没有宣称完全恢复论文未公开的评分细则。原始问题、金标、35 个 ID、全部来源和运行中代码哈希核对一致，没有新跑全量。

最终结果、门槛、两套分数、误判及 SMT 重放以 `runs/validation35-v1/comparison.md`、`validation.json`、`scoring_disagreements.json`、`error_cases.json`、`abstentions.json` 和 `smt_replay.json` 为准。35 题属于开发验证，不声称已完成论文原模型/67 题的全量复现或恢复全部未公开资产。
